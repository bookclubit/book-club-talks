Как показывать Наведите на σ, условие или animals — подсветится соответствующая часть SQL.

Текст В реляционной алгебре то же самое пишется одной строкой: sharks равно сигма с условием family равно Sharks от animals. Сигма — оператор выбора: возвращает только тех животных, которые соответствуют условию. SQL весьма близко следует структуре реляционной алгебры: SELECT звёздочка FROM animals WHERE family равно Sharks.

Текст В декларативных языках описывают шаблон нужных данных: каким условиям должны соответствовать результаты и как их преобразовать — отсортировать, сгруппировать, агрегировать. Но не то, как этого добиться. Какие индексы и методы соединения использовать, в каком порядке выполнять части запроса — решает оптимизатор.

Как показывать В русском издании в сноске формула переведена: «акулы = σ семейство = Акулы (животные)».

Переход Хорошо, запрос короче. Но короткость — не главное.

04Почему декларативно · 1

Запрос не знает реализации — базе можно ускоряться

База хочет освободить место на диске и перетасовать записи. Не сломает ли она существующие запросы?

Императивный код · порядок зашит
Great WhiteTiger SharkHammerhead
// а вдруг код рассчитывает на порядок?
const first = getSharks()[0];

База не может быть уверена, важен ли порядок для кода, — значит, трогать данные опасно

SQL · порядок не обещан
Great WhiteTiger SharkHammerhead
SELECT * FROM animals WHERE family = 'Sharks';
-- нужен порядок? скажите явно: ORDER BY

Результат — множество, порядок не гарантирован. Базе можно перекладывать записи как угодно

Цена
Возможностей у SQL меньше, но именно поэтому у оптимизатора гораздо больше свободы

Текст Декларативные языки привлекательны, потому что короче и удобнее императивных API. Но важнее другое: они скрывают подробности реализации ядра базы, и у СУБД появляется возможность повышать производительность, не меняя запросов.

Текст Пример из книги. Императивный код выше возвращает животных в определённом порядке. Допустим, базе понадобилось незаметно освободить неиспользуемое место на диске, и для этого надо перетасовать записи — порядок изменится. Сможет ли база сделать это безопасно? Запрос на SQL не гарантирует никакого порядка, поэтому ему всё равно. А если запрос написан императивным кодом, база не может знать, рассчитывает ли код на порядок.

Текст Функциональность SQL более ограничена, но это даёт гораздо больше возможностей для автоматической оптимизации.

Как показывать Строки в обеих колонках меняются местами — слева это риск, справа норма. Строка с getSharks()[0] — моя иллюстрация.

var liElements = document.getElementsByTagName("li");
for (var i = 0; i < liElements.length; i++) {
  if (liElements[i].className === "selected") {
    var children = liElements[i].childNodes;
    for (var j = 0; j < children.length; j++) {
      var child = children[j];
      if (child.nodeType === Node.ELEMENT_NODE &&
          child.tagName === "P") {
        child.setAttribute("style", "background-color: blue");
      }
    }
  }
}

Текст MapReduce — модель программирования для обработки больших объёмов данных блоками на множестве машин, её активно продвигала Google. В ограниченном виде MapReduce поддерживают некоторые NoSQL-хранилища, включая MongoDB и CouchDB, — как механизм запросов только на чтение по многим документам. Подробно MapReduce разбирается в главе 10, сейчас — коротко и на примере MongoDB.

Текст MapReduce — ни декларативный язык запросов, ни полностью императивный API. Нечто среднее: логика запроса выражается фрагментами кода, которые фреймворк вызывает многократно. Основа — функции map, она же collect, и reduce, она же fold или inject, из функциональных языков. Нам они знакомы по массивам в JavaScript.

Текст То же самое через MapReduce в MongoDB. Фильтр только по акулам задаётся декларативно — это расширение MongoDB к модели MapReduce. Функция map на JavaScript вызывается один раз для каждого документа, подходящего под query, и this в ней — сам документ. Она порождает ключ — строку из года и месяца, например «2013-12» или «2014-1», — и значение — количество животных в наблюдении.

Текст Пары «ключ — значение», порождённые map, группируются по ключу, и для всех пар с одинаковым ключом, то есть с одним месяцем, один раз вызывается reduce. Она суммирует количество животных за месяц. Итог записывается в коллекцию monthlySharkReport.

Текст MapReduce — модель программирования довольно низкого уровня, предназначенная для распределённых вычислений на кластерах. Языки более высокого уровня, такие как SQL, можно реализовать как конвейер операций MapReduce — об этом глава 10. Но существует и множество распределённых реализаций SQL без MapReduce. Текст Неудобство MapReduce: приходится писать две тщательно согласованные функции, что обычно сложнее одного запроса. А декларативный язык даёт оптимизатору больше возможностей улучшить производительность.

MongoDB 2.2: конвейер агрегирования

Декларативный язык запросов: по возможностям — подмножество SQL, по синтаксису — JSON

aggregation pipeline
db.observations.aggregate([  { $match: { family: "Sharks" } },  { $group: {    _id: {      year:  { $year:  "$observationTimestamp" },      month: { $month: "$observationTimestamp" }    },    totalAnimals: { $sum: "$numAnimals" }  } }]);
SQL · для сравнения
SELECT date_trunc('month', …) AS month,       sum(num_animals)FROM observationsWHERE family = 'Sharks'GROUP BY month;

Как показывать Наведите на пару в середине — подсветятся соответствующие части обоих запросов.

Текст Именно из-за этих неудобств в версии 2.2 в MongoDB добавили поддержку декларативного языка запросов — конвейера агрегирования, aggregation pipeline. Тот же подсчёт акул: стадия $match фильтрует, $group группирует по году и месяцу, $sum суммирует.

Текст По выразительности конвейер напоминает подмножество SQL, но использует синтаксис на основе JSON, а не фразы в стиле английского языка. Это, вероятно, дело вкуса.

Как показывать Уже после книги, начиная с MongoDB 5.0, mapReduce объявлен устаревшим: документация советует конвейер агрегирования.
