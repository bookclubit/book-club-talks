Что такое реактивность?

Способность системы обновляться сама в ответ на изменение данных.

  • Для пользователя — мгновенная реакция интерфейса на его действия
  • Для фреймворка — автоматическое обновление интерфейса по изменению состояния
AB
1 2 = A1 * 10 20
2 5 = A1 + A2 7
3 итог = B1 + B2 27

Электронная таблица

Меняем A1 — и все формулы, которые на неё ссылаются, пересчитываются сами. Причём каскадом: B3 зависит не от A1 напрямую, а от B1 и B2.

Никто не вызывает «пересчитай таблицу» руками — связи между ячейками описаны один раз, дальше система следит сама. В веб-фреймворках реактивность решает ту же задачу — связывает данные и интерфейс.

Суть реактивного программирования

Изменение одного состояния приводит к каскадному изменению других. Меняем count — и всё, что от него зависит, обновляется само.

Вычисляемое значение count × 2 = 6
Стиль

Вопрос, на который каждый фреймворк отвечает по-своему: как узнать, что именно зависит от изменившегося значения — и как обновить только это.

Vue 2: реактивность через Object.defineProperty

Каждое свойство объекта превращается в пару геттер/сеттер: чтение записывает зависимость, запись уведомляет об изменении.

  • Object.definePropertyподменяет свойство парой геттер/сеттер
  • trackна чтении запоминает, кто зависит от свойства
  • triggerна записи уведомляет всех, кто запомнился
vue2-reactivity.js
// Упрощённая реализация Vue 2
function defineReactive(obj, key, val) {
  Object.defineProperty(obj, key, {

    get() {
      track(key); // отслеживаем, что свойство прочитано
      return val;
    },


    set(newVal) {
      if (newVal !== val) {
        val = newVal;
        trigger(key); // уведомляем об изменении
      }
    }

  });
}


const data = { count: 0 };
defineReactive(data, 'count', 0);

Тот же приём, что в электронной таблице: чтение — подписка, запись — сигнал.

Точный, но заранее размеченный

Vue 2 знает про зависимости больше React: обновляется не компонент, а конкретные эффекты. Но перехват ставится по одному свойству — и всё, что не разметили заранее, выпадает из реактивности.

Vue 2: где ломается

Реактивным становится только то, что размечено при инициализации: каждое свойство обёрнуто в «наручники» геттера и сеттера. Три случая, когда наручников не оказывается.

  • Object.definePropertyставится по одному свойству и только при инициализации
  • Vue.set и Vue.deleteобёртки, чтобы добавить или удалить свойство «через Vue»
  • рекурсивный обходвложенные объекты размечаются целиком, сразу и до конца

Vue 3: реактивность через Proxy

Object.defineProperty заменили на ES6 Proxy: он оборачивает объект целиком и перехватывает любые операции — чтение, запись, добавление, удаление.

  • Proxyпосредник, который стоит перед объектом целиком
  • ловушки get, set, deletePropertyперехватывают любую операцию, включая новые свойства
  • track и triggerте же, что в Vue 2: подписка на чтении, уведомление на записи
vue3-reactivity.js
// Упрощённая реализация Vue 3
function reactive(obj) {

  return new Proxy(obj, {


    get(target, key) {
      track(target, key); // отслеживаем зависимость
      return target[key];
    },


    set(target, key, value) {
      target[key] = value;
      trigger(target, key); // уведомляем об изменении
      return true;
    }

  });
}

const state = reactive({ count: 0 });
state.count = 1;        // работает!
state.newProp = 'hello'; // тоже работает — Proxy перехватывает

Что дал Proxy

Отслеживаются добавление и удаление свойств, массивы работают без хаков, производительность выше — обёртка ставится одна на объект, а не по одной на каждое свойство.

Цена — Proxy есть только в ES6+: поддержку IE11 Vue 3 потерял.

Proxy перехватывает всё

Одна и та же операция над состоянием — и то, что о ней узнаёт Vue 3 с Proxy и Vue 2 с геттерами и сеттерами.

  • Proxyодна обёртка на весь объект — Vue 3
  • Object.definePropertyпара геттер/сеттер на каждое свойство — Vue 2

Почему проверяется всё дерево

Angular не знает, что именно изменилось: он знает только, что закончилась асинхронная операция. Единственный надёжный способ не пропустить изменение — перепроверить привязки у всех компонентов.

Angular 2026

Сигнал сам знает, кто его читает. Значит, спрашивать «а вдруг что-то изменилось» больше не надо — и Zone.js становится не нужен.

  • Signal APIsignal, computed, effect: значение со списком своих читателей

import { Component, signal, computed } from '@angular/core';

@Component({
  template: `

    <p>Счёт: {{ count() }}</p>

  doubled = computed(() => this.count() * 2);

Svelte 4: как работает $:

Svelte — компилятор. То, что другие фреймворки делают в браузере, он делает один раз при сборке: читает файл, находит присваивания и сам дописывает вызовы обновления.

  • компилятор Svelteчитает файл при сборке, а не следит за ним в браузере
  • $:метка реактивного выражения — его зависимости берутся из текста
  • $$invalidateвызов, который компилятор дописывает за вас после присваивания

  function increment() {
    count += 1;

<button on:click={increment}>

Реактивность без рантайма

В браузер уезжает не фреймворк, а готовый код именно этого компонента. Наблюдать за переменными некому — за них всё решил компилятор, пока читал файл.

Svelte 4: где ломается $:

Всё держится на том, что компилятор видит присваивание в тексте файла. Стоит вынести его за границу .svelte — и дописывать $$invalidate становится некуда.

Svelte 5: руны

Руна — явный вызов вместо неявного правила. Компилятор превращает её в сигнал, а зависимости собираются во время выполнения — по факту чтения, а не по тексту файла.

  • $state, $derived, $effectявные вызовы вместо неявных правил
  • .svelte.tsобычный файл, который тоже проходит через компилятор рун
  • сбор зависимостей в рантаймеподписка получается из факта чтения

  console.log('счёт:', count, 'удвоено:', doubled);

export function increment() {
  count++;

  return count;

Что изменилось по сути

Зависимости больше не выводятся из текста файла. Их собирает сама программа во время работы: прочитал сигнал — попал к нему в читатели. Ровно та же модель, что у Solid и Vue 3.6.

Solid: сигнал как пара [getter, setter]

Компонент выполняется один раз. Дальше живут только сигналы — и обновляют ровно те DOM-узлы, которые их читают.

  • createSignalпара [getter, setter]: читать и писать — разные функции
  • createMemo и createEffectпроизводное значение и эффект, оба подписываются сами
  • компиляция JSXсразу в создание DOM-узлов, без виртуального дерева
Counter.jsx
import { createSignal, createMemo, createEffect } from 'solid-js';

function Counter() {

  const [count, setCount] = createSignal(0);



  const doubled = createMemo(() => count() * 2);



  createEffect(() => {
    console.log('Счёт:', count());
  });


  return (
    <>

      <div>{count()}</div>
      <div>{doubled()}</div>


      <button onClick={() => setCount(c => c + 1)}>
        Увеличить
      </button>

    </>
  );
}

Компонент — это функция настройки

В React функция компонента вызывается на каждое изменение. В Solid она вызывается один раз: её задача — создать узлы и подписки. Дальше работают только сигналы, а на частых точечных обновлениях это даёт 50–70% выигрыша.

Qwik: интерактивность без ожидания

Гидратация — это повторный запуск всего приложения в браузере ради того, что сервер уже посчитал. Qwik её не делает: и состояние, и адрес каждого обработчика он кладёт прямо в HTML.

  • component$ и onClick$границы, по которым компилятор режет код на чанки
  • сериализация состояниясостояние и подписки уезжают в HTML вместе с разметкой
  • загрузчик ~1.6 КБловит событие и подгружает нужный чанк — больше ничего
counter.tsx — что пишет разработчик
import { component$, useSignal } from '@builder.io/qwik';

export default component$(() => {
  const count = useSignal(0);


  return (
    <button onClick$={() => count.value++}>
      Счёт: {count.value}
    </button>
  );

});

HTML + состояние интерактивно чанк обработчика — по клику
ждать нечего: ~1.6 КБ и всё
Обе дорожки стартуют вместе — смотрите, когда загорится «интерактивно»

Почему это O(1)

Гидратация стоит тем дороже, чем больше приложение: браузер обязан пройти всё дерево. Возобновляемость не зависит от размера вовсе — загружается один и тот же загрузчик, а код обработчика приходит только тогда, когда до него дошло дело.

На 50–80% быстрее React по времени до интерактивности — и, что важнее, это время постоянно: оно не зависит от размера приложения.
