Что такое реактивность?

Способность системы обновляться сама в ответ на изменение данных. Для пользователя — мгновенная реакция интерфейса на его действия, для фреймворка — автоматическое обновление интерфейса по изменению состояния.

AB
1 2 = A1 * 10 20
2 5 = A1 + A2 7
3 итог = B1 + B2 27

Электронная таблица

Меняем A1 — и все формулы, которые на неё ссылаются, пересчитываются сами. Причём каскадом: B3 зависит не от A1 напрямую, а от B1 и B2.

Никто не вызывает «пересчитай таблицу» руками — связи между ячейками описаны один раз, дальше система следит сама.

В веб-фреймворках реактивность решает ту же задачу — связывает данные и интерфейс. Дальше в докладе — пять разных способов эту связь построить.

Суть реактивного программирования

Изменение одного состояния приводит к каскадному изменению других. Меняем count — и всё, что от него зависит, обновляется само.

Вопрос, на который каждый фреймворк отвечает по-своему: как узнать, что именно зависит от изменившегося значения — и как обновить только это.

React: цена одного состояния

Компонент — функция, и при каждом изменении count она выполняется целиком. Нажмите на подсвеченную строку — справа появится пояснение.

Counter.jsx
import { useState } from 'react';

function Counter() {

  const [count, setCount] = useState(0);


  console.log('Компонент перерендеривается!');


  return (
    <div>

      <p>Счёт: {count}</p>


      <button onClick={() => setCount(count + 1)}>
        Увеличить
      </button>

    </div>
  );
}

Крупнозернистая реактивность: единица обновления — компонент, а не значение.

Компонент как единица обновления

React не знает, какие узлы зависят от count. Он знает только, что компонент изменился, — и выясняет разницу сравнением деревьев. Отсюда и мемоизация: useMemo, useCallback, React.memo нужны, чтобы лишний раз не считать заново.

Vue 2: реактивность через Object.defineProperty

Каждое свойство объекта превращается в пару геттер/сеттер: чтение записывает зависимость, запись уведомляет об изменении.

vue2-reactivity.js
// Упрощённая реализация Vue 2
function defineReactive(obj, key, val) {
  Object.defineProperty(obj, key, {

    get() {
      track(key); // отслеживаем, что свойство прочитано
      return val;
    },


    set(newVal) {
      if (newVal !== val) {
        val = newVal;
        trigger(key); // уведомляем об изменении
      }
    }

  });
}


const data = { count: 0 };
defineReactive(data, 'count', 0);

Тот же приём, что в электронной таблице: чтение — подписка, запись — сигнал.

Точный, но заранее размеченный

Vue 2 знает про зависимости больше React: обновляется не компонент, а конкретные эффекты. Но перехват ставится по одному свойству — и всё, что не разметили заранее, выпадает из реактивности.

Vue 2: где ломается

Каждое свойство обёрнуто в «наручники» геттера и сеттера. Добавьте новое — и увидите, что Vue его не замечает.

data

count геттер + сеттер
title геттер + сеттер

Vue отслеживает 2 свойства из 2.

1

Новые свойства не отслеживаются. Свойство должно существовать в data при инициализации — иначе нужен Vue.set().

2

Массивы. Запись по индексу arr[0] = 5 не реактивна: у индексов нет своих геттеров и сеттеров.

3

Рекурсивный обход. Пара геттер/сеттер нужна каждому свойству вложенных объектов — инициализация большого состояния стоит времени.

Vue 3: реактивность через Proxy

Object.defineProperty заменили на ES6 Proxy: он оборачивает объект целиком и перехватывает любые операции — чтение, запись, добавление, удаление.

vue3-reactivity.js
// Упрощённая реализация Vue 3
function reactive(obj) {

  return new Proxy(obj, {


    get(target, key) {
      track(target, key); // отслеживаем зависимость
      return target[key];
    },


    set(target, key, value) {
      target[key] = value;
      trigger(target, key); // уведомляем об изменении
      return true;
    }

  });
}

const state = reactive({ count: 0 });
state.count = 1;        // работает!
state.newProp = 'hello'; // тоже работает — Proxy перехватывает

Нажмите на строку, чтобы разобрать ловушку.

Что дал Proxy

Отслеживаются добавление и удаление свойств, массивы работают без хаков, производительность выше — обёртка ставится одна на объект, а не по одной на каждое свойство.

Цена — Proxy есть только в ES6+: поддержку IE11 Vue 3 потерял.

Proxy перехватывает всё

Объект обёрнут прозрачной плёнкой: любое действие с ним сначала проходит через ловушку. Нажмите на операцию — посмотрите, что видит Vue.

Vue в 2026: Alien Signals

Vue 3.6 (релиз-кандидат) полностью переписывает @vue/reactivity на основе библиотеки Alien Signals (её автор — Johnson Chu).

Модель

Сигналы

Та же сигнальная модель, что у Solid и Svelte 5. Vue приходит к ней своим путём — снаружи API остаётся прежним: ref, computed, watch.

Область действия

По умолчанию

Работает для всех компонентов, а не только для тех, которые переписали: код приложения менять не нужно.

Результат

Скорость и память

Значительно меньше расход памяти и быстрее распространение изменений по графу зависимостей.

Обратите внимание: реактивность и рендеринг — разные слои. Alien Signals меняет первый, Vapor Mode со следующего слайда — второй.

Vapor Mode: отказ от виртуального DOM

Новая стратегия компиляции: вместо виртуального дерева генерируется прямой императивный код обновления DOM. Включается атрибутом vapor в теге <script setup>.

Angular: обнаружение изменений на Zone.js

Zone.js «патчит» все асинхронные операции браузера — setTimeout, Promise, XHR, клики — и после каждой запускает Change Detection. Нажмите кнопку в дереве.

counter.component.ts
@Component({
  selector: 'app-counter',
  template: `<p>{{ count }}</p><button (click)="increment()">+1</button>`
})
export class CounterComponent {
  count = 0;

  increment() {
    this.count++; // Zone.js перехватывает клик
  }              // и запускает Change Detection
}

Angular в 2026: сигналы и zoneless

С Angular 21 Zone.js больше не обязателен, с Angular 22 новые проекты создаются zoneless по умолчанию. Обновляются только компоненты, которые читают изменившийся сигнал.

counter.component.ts
import { Component, signal, computed } from '@angular/core';

@Component({
  selector: 'app-counter',
  template: `
    <p>Счёт: {{ count() }}</p>
    <p>Удвоено: {{ doubled() }}</p>
    <button (click)="increment()">+1</button>`
})
export class CounterComponent {
  count = signal(0);                          // состояние
  doubled = computed(() => this.count() * 2); // производное

  increment() {
    this.count.update(v => v + 1);
  }
}

// bootstrap без Zone.js (Angular 21+)
bootstrapApplication(AppComponent, {
  providers: [provideZonelessChangeDetection()]
});

Svelte 4: магия $:

Зависимости компилятор определял статически — по тексту файла. Пока код лежит в .svelte, всё работает. Нажмите «Вынести в файл».

Counter.svelte
<script>
  let count = 0;
  let doubleCount = 0;

  // Реактивное выражение — пересчитывается при изменении count
  $: doubleCount = count * 2;

  // Реактивный блок — выполняется при изменении зависимостей
  $: {
    console.log('count изменился:', count);
  }

  function increment() {
    count += 1; // простое присваивание — Svelte отследит сам
  }
</script>

<button on:click={increment}>
  Нажато {count} раз (удвоено: {doubleCount})
</button>
count += 1 отслеживается doubleCount

Svelte 5: руны

Руны (runes) — явный API вместо магии: $state, $derived, $effect, $props. Главное — они работают не только в компоненте.

Counter.svelte
<script>
  let count = $state(0);
  let doubled = $derived(count * 2);

  $effect(() => {
    console.log('Счёт изменился:', count);
  });
</script>

<button onclick={() => count++}>
  {count} (удвоено: {doubled})
</button>
counter.svelte.ts
// реактивность ВНЕ компонента
let count = $state(0);

export function increment() {
  count++;
}

export function getCount() {
  return count;
}

Тот же $state — в обычном .ts-файле с суффиксом .svelte.ts. Состояние можно вынести из компонента и переиспользовать.

Руны — реактивность без границ файла компонента. И, что важнее, без статического анализа: зависимости собираются во время выполнения, как у сигналов.

Solid: сигнал как пара [getter, setter]

Компонент выполняется один раз. Дальше живут только сигналы — и обновляют те DOM-узлы, которые их читают. Нажмите «Увеличить» в обеих панелях справа.

Counter.jsx
import { createSignal, createMemo, createEffect } from 'solid-js';

function Counter() {
  // createSignal возвращает [getter, setter]
  const [count, setCount] = createSignal(0);

  // производный сигнал — пересчитывается при изменении count
  const doubled = createMemo(() => count() * 2);

  createEffect(() => {
    console.log('Счёт:', count());
  });

  return (
    <>
      <div>{count()}</div>   // обновится только этот узел
      <div>{doubled()}</div> // и этот
      <button onClick={() => setCount(c => c + 1)}>
        Увеличить
      </button>
    </>
  );
}

Что такое Qwik

Фреймворк, построенный на возобновляемости (resumability): вместо гидратации приложение продолжает работу с того места, где остановился сервер. Создатель — Мишко Хевери. Тот же, что придумал Angular.

2022–2024 Экосистема Qwik City, интеграции, серверные адаптеры

Автор Angular второй раз переосмысляет реактивность — и на этот раз спорит не с обновлением DOM, а с самой загрузкой приложения.

Qwik: интерактивность без ожидания

Сервер сериализует состояние прямо в HTML, клиент получает ~1.6 КБ JavaScript, гидратации нет вообще: обработчики подгружаются в момент взаимодействия. Нажмите «Загрузка страницы».

counter.tsx
import { component$, useSignal, useTask$ } from '@builder.io/qwik';

export default component$(() => {
  const count = useSignal(0);

  // useTask$ — реактивный эффект
  useTask$(({ track }) => {
    track(() => count.value); // явная подписка на сигнал
    console.log('Счёт изменился:', count.value);
  });

  return (
    <button onClick$={() => count.value++}>
      Счёт: {count.value}
    </button>
  );
});

$ в component$ и onClick$ — граница ленивой загрузки: компилятор вырезает этот код в отдельный чанк.

Куда всё идёт

Главный вывод 2026 года: индустрия сходится к сигнальной модели реактивности и уходит от виртуального DOM. Vue, Angular, Svelte — все пришли к сигналам. Qwik добавляет к этому возобновляемость.

Время до интерактивности и размер приложения

1

Сигналы победили. Точное знание «что от чего зависит» оказалось дешевле, чем сравнение деревьев.

2

Virtual DOM — не обязателен. Vapor Mode, Svelte, Solid и Qwik обновляют DOM напрямую.

3

Дальше — загрузка. Когда обновления стали точечными, узким местом стало время до интерактивности: здесь и появляется возобновляемость.
