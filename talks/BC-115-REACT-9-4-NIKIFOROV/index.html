Глава 9 · Серверные действия

«use server»: функции сервера, вызываемые с клиента

Серверные компоненты — не единственная новинка. В паре с ними работает директива «use server», превращающая обычную функцию в серверное действие (server action).

  • Любая асинхронная функция может начинаться с «use server» — сигнал React и компоновщику: вызывать можно с клиента, выполнять — только на сервере.
  • Вызов действия на клиенте — это сетевой запрос с сериализованной копией всех аргументов.
  • Возвращаемое значение сериализуется и приходит обратно клиенту.
async function requestUsername(formData) {
  "use server";
  const username = formData.get("username");
  // выполняется только на сервере
}
Знакомая логика: «use client» помечает границу клиентского пакета, «use server» — границу серверных функций. Две директивы — два направления через сеть.
Синтаксис

Пометить функцию — или сразу весь файл

Директива в теле функции

async function requestUsername(formData) {
  "use server";
  // ...
}

Точечно: серверным действием становится одна конкретная функция.

Директива в начале файла

"use server"; // первая строка файла

export async function likePost(id) { /* ... */ }
export async function follow(userId) { /* ... */ }

Весь экспорт файла — серверные действия. Их можно использовать где угодно, включая импорт в клиентский код.

Формы и мутации

Форма, которая работает до загрузки JavaScript

React даёт первоклассные примитивы для форм: серверное действие передаётся прямо в action, и при отправке формы происходит сетевой запрос к серверной функции.

// App.js
async function requestUsername(formData) {
  "use server";
  const username = formData.get("username");
  // ...
}

export default function App() {
  return (
    <form action={requestUsername}>
      <input type="text" name="username" />
      <button type="submit">Request</button>
    </form>
  );
}
  • При вызове действия из формы React сам передаст её FormData первым аргументом.
  • Это прогрессивное улучшение: форму можно отправить ещё до того, как загрузился JS-пакет.
  • Никакого ручного fetch, onSubmit и preventDefault — мутация описывается одной функцией.
За пределами форм

Действие + useTransition: лайк без формы

Серверные действия можно вызывать из любого места клиентского кода. Вызов в переходе даёт индикатор загрузки, оптимистичные обновления и обработку ошибок.

"use client";
import incrementLike from "./actions";
import { useState, useTransition } from "react";

function LikeButton() {
  const [isPending, startTransition] = useTransition();
  const [likeCount, setLikeCount] = useState(0);

  const onClick = () => {
    startTransition(async () => {
      // ждём promise, чтобы прочитать результат
      const currentCount = await incrementLike();
      setLikeCount(currentCount);
    });
  };

  return (
    <>
      <p>Total Likes: {likeCount}</p>
      <button onClick={onClick} disabled={isPending}>Like</button>
    </>
  );
}
  • startTransition оборачивает вызов действия — пока запрос летит на сервер, isPending истинно и кнопка выключена.
  • Возвращаемое значение действия — обычный promise: await — и результат у нас.
  • Тот же механизм открывает дорогу оптимистичным обновлениям и обработке непредвиденных ошибок.

Помним про безопасность

Серверные действия — открытые endpoint'ы: их можно вызвать из любого места клиентского кода. Относиться к ним стоит так же строго, как к любому публичному API — с проверкой прав и валидацией входа.

Это API для фреймворков

В ванильном React работа с директивами громоздка и требует немалой настройки. На практике серверные действия предназначены для библиотек и фреймворков — Next.js и подобных.

Тем не менее это мощная функция, открывающая множество интересных вариантов использования — от форм до произвольных мутаций.
Главные выводы

Если запомнить только это

  • Серверное действие — асинхронная функция с «use server»: вызывается с клиента, выполняется на сервере.
  • Аргументы и результат сериализуются и ездят по сети — как пропсы у серверных компонентов.
  • В формах действие передаётся в action, React сам подставляет FormData — и форма работает даже до загрузки JS.
  • Вне форм действия дружат с useTransition: индикаторы загрузки, оптимистичные обновления, обработка ошибок.
  • Это открытые endpoint'ы и API уровня фреймворков — использовать через Next.js и аналоги, не забывая о безопасности.
